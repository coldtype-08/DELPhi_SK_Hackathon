## 1. AS-IS — 문제는 하나가 아니라 둘이다

우리가 다루는 데이터는 **의료진 면담 기록**이다. MSL이 의사를 만나고 남기는 기록으로, 사내에 실제로 축적돼 있다(면담 기록·하이라이트 묶음·학회 참관 보고서 등 **docx 약 300건**, 전부 영어). 문제를 하나로 뭉쳐 말하면 해법도 뭉개지므로 **두 갈래로 나눈다.**

| | **① 축적분 (stock)** — 이미 쌓인 것 | **② 유입분 (flow)** — 지금도 쌓이는 것 |
|---|---|---|
| 현재 상태 | 자유 서술 문서 수백 건. 스키마 없음, 검색은 파일명·키워드 수준 | 면담 후 각자 자유 형식 메모. 다음 면담도 같은 방식 |
| 그래서 뭘 하나 | 필요할 때 **사람이 일일이 찾고 읽고 요약**한다. 질문 하나에 며칠 | 남길 항목의 기준이 없어 **그때그때 다른 것을 적는다** |
| 무엇이 사라지나 | 여러 문서에 흩어진 **반복 신호**. 한 문서만 보면 일화, 열 문서를 세면 패턴인데 셀 수가 없다 | ① 적을 때 기준이 없어 **빠뜨리고** ② 나중에 읽는 사람은 그 자리에 없었기 때문에 **맥락을 복원하지 못한다** |
| 비용의 이름 | **Insight Latency** — 신호가 데이터에 존재한 시점과, 사람이 그것을 알게 되는 시점 사이의 간격 | **재발** — 이번 달 축적분을 정리해도 다음 달에 같은 문제가 다시 쌓인다 |

### 1.1 이 프로젝트의 출발점이 된 관찰

**축적분만 고치는 것은 청소이고, 유입분을 고치는 것이 설계다.** 문서 요약·검색 도구는 ①만 다룬다. ①만 고치면 매달 같은 청소를 반복하고, 청소하는 동안에도 새 문서는 같은 형식으로 쌓인다. 그래서 DELPHi는 **입구를 두 개** 갖는다 — 이것이 기능이 많아 보이는 이유이고, 실은 문제가 둘이기 때문이다.

또 하나: 이 데이터는 **분석 대상이 아니라 근거 대상**이다. 의료·규제 영역에서 "AI가 요약해준 결론"은 그 자체로 쓸 수 없다. 누가 언제 무슨 말을 했는지 원문까지 되짚을 수 없으면 어떤 판단에도 못 올린다. 그래서 우리의 구조화는 **요약이 아니라 근거 연결**이어야 한다.

## 2. TO-BE — 입구를 둘 다 막고, "AI Readable"을 정의한다

| | AS-IS | **TO-BE** | 구현 |
|---|---|---|---|
| ① 축적분 | 사람이 찾아 읽고 요약 | **Sense**: 원문 근거가 연결된 구조화 데이터로 전환. 반복이 SQL로 세어진다 | `sense/extract·normalize·grade·aggregate` |
| ② 유입분 | 자유 형식 메모 → 나중에 누군가 다시 읽음 | **Field**: 대화 직후 그 자리에서 **정해진 항목**을 채운다. 사후 정리 단계가 아예 없다 | `GET /field/form-config` 기반 동적 폼 (하드코딩 금지) |
| 항목을 누가 정하나 | 정해진 것이 없음 | **스키마 초안도 AI가 낸다** → 사람이 확정 (Contract 부트스트랩) | `/contract/provenance` 화면 |
| 새 개념이 나오면 | 자유 서술 안에 묻힌다 | 반복되면 **수집 구조 자체가 개선**된다 (SCP → 새 버전 → 폼 변경) | 구조 루프, docs/01 §3 |
| 판단이 내려지면 | 문서로 남고 끝 | **다음 수집을 겨냥한다** (Action Item → 현장 체크리스트) | 실행 루프, docs/01 §3 |

### 2.1 "AI Readable data"의 정의 — 수식어가 아니라 사양

이 말이 막연하면 아무 검증도 못 한다. DELPHi에서 AI Readable은 **다섯 조건을 만족하는 레코드**를 뜻한다 (전부 `docs/02 Data Contract`에 코드화되어 있다).

| 조건 | 없으면 무엇이 안 되나 |
|---|---|
| ① **정해진 스키마** (versioned) — 필드·허용값이 고정 | 같은 개념이 매번 다르게 들어가 집계가 불가 |
| ② **원문 근거 포인터** (doc_id + 문자 위치) | 되짚을 수 없으니 어떤 판단에도 못 올린다 |
| ③ **목적 도메인 태그** (`purpose_domain`) | 누가 무엇을 봐도 되는지 판단할 수 없다 |
| ④ **언어 중립 canonical** (EN·KO → 같은 코드) | 언어가 늘면 집계가 쪼개진다 |
| ⑤ **상태** (CANDIDATE / APPROVED / REJECTED) | 검증된 것과 안 된 것이 같은 숫자에 섞인다 |

즉 "AI가 읽을 수 있다"는 것은 *텍스트를 모델에 넣을 수 있다*는 뜻이 아니다. **집계·추적·권한 판단이 가능한 형태**라는 뜻이다. 텍스트를 벡터DB에 넣는 것으로는 ②③④⑤ 중 하나도 얻지 못한다.

## 3. 혁신성 — AI 네이티브 관점의 설계

"AI를 얼마나 많이 쓰나"가 아니라 **무엇을 어디에 두는가**를 설계했다. 세 층으로 갈라져 있고, 경계가 코드에 있다.

| | 담당 | 대표 예 | 왜 여기인가 |
|---|---|---|---|
| **AI (LLM)** | 판단의 후보를 만든다 | 스키마 초안 제안 · 비정형→구조화 추출 · 용어 정규화 후보 · 외부 근거 교차검증(Screen 4종) · 다중 관점 심의와 권고(Board·CEO) · 후속 액션 제안 | 언어를 다루는 일, 그리고 **틀려도 사람이 되돌릴 수 있는 일** |
| **사람** | 확정한다 | Contract 확정(Steward) · 추출값 승인·수정·반려 · 가설 승인·보류·기각 · Action Item 채택 | 결과에 책임이 따르는 일. **Board·CEO 에이전트에게 승인 권한이 없다** |
| **결정론 코드** | 셈과 게이트 | 모든 수치(SQL) · 임계값 가설 생성 · 검토등급 H/M/L · 상태 전이 · 권한 게이트 · `label_scope` 파생 | 재현되어야 하는 일. 같은 입력이면 같은 값이 나와야 한다 |

기존 방식과 갈리는 지점을 다섯 개로 좁히면:

1. **요약이 아니라 근거 연결** — 원문 없는 주장은 저장 자체를 거부한다(evidence pointer 필수).
2. **수치를 LLM이 만들지 않는다** — 반복 횟수·출처 수·추이는 전부 SQL. AI를 덜 쓰는 게 아니라, **믿을 수 있게 쓰는 방법**이다.
3. **권한이 화면이 아니라 쿼리에 있다** — 목적 도메인 게이트를 서버가 강제하고, 권한 밖은 빈 배열이 아니라 403으로 거부한다(조용한 누락 금지).
4. **하지 않는 것을 코드가 막는다** — 개별 처방성향 점수화·매출 예측·프로모션 문구 생성은 구현하지 않고, Action Item의 `target` enum에는 **상업 실행 값이 아예 없다**. 규칙을 문서로 약속하는 대신 타입으로 불가능하게 만들었다.
5. **루프가 둘이다** — 판단이 다음 수집을 겨냥하고(실행 루프, 매 심의마다), 반복되는 새 개념은 수집 구조를 바꾼다(구조 루프, 드물게).

## 4. 목표와 기대효과 — 수치와 측정 설계

기획서에 선언한 정량 목표를 그대로 유지한다. **해커톤은 이 숫자를 달성했다고 주장하지 않는다** — 구조를 증명하고, 숫자는 파일럿에서 baseline과 비교해 잰다.

| 지표 | 목표 | 정의 (언제 → 언제) | 어떻게 잴 것인가 |
|---|---|---|---|
| **Data Latency** | 70% ↓ | 원석이 생긴 시점 → 집계 가능한 구조화 데이터가 된 시점 | 파일럿: 동일 문서군을 사람 정리 vs DELPHi로 처리해 소요시간 비교. Field 수집분은 **사후 정리 단계가 0**이므로 구조적으로 단축 |
| **Insight Latency** | 50% ↓ | 신호가 데이터에 존재한 시점 → 사람이 판단 가능한 형태(가설+근거+권고)로 본 시점 | 임계 도달 → 가설 자동 생성까지의 시간을 로그로 측정. 현재는 "사람이 전수 검토를 마쳐야 시작"이 baseline |
| **반복 재분류** | 70% ↓ | 같은 개념을 다시 분류·정리하는 작업량 | unmapped_terms 비율과 SCP 승격 건수로 추적. vocab이 흡수하는 만큼 줄어든다 |
| **reviewer acceptance** | 90%+ | 검토 완료분 중 승인 비율 (docs/02 §5.5) | 합성 코퍼스 ground truth로 **해커톤에서도 참고 수치 산출 가능** (docs/03 §4) |
| **실행 지연** (08/21 추가) | — | 판단이 내려진 시점 → 현장 수집에 반영된 시점 | 액션별 `delivered_at`과 참조 수집 카운트로 직접 측정. 이 지표는 **DELPHi가 없으면 측정 자체가 불가능**했다 |

각 지표를 화면에서 어떻게 증명하는지는 `docs/00 §1.2`에 경로까지 적어두었다.

> ⟨확인 필요 — 사람이 채울 것⟩ AS-IS baseline 실측: 지금 이 데이터로 질문 하나에 답하는 데 실제로 며칠이 걸리는지, 월 몇 건의 면담이 쌓이는지. 이 두 숫자가 있으면 목표치가 "인용"에서 "계산"이 된다. 없으면 목표치로만 제시한다(허위 정밀도 금지).

## 5. 임팩트 범위 — 어디까지 확장되는가

"확장 가능합니다"는 주장이 아니다. **확장 지점을 코드 위치로 지목**한다.

| 확장 축 | 무엇을 바꾸나 | 바뀌지 않는 것 |
|---|---|---|
| 다른 제품(약물) | `contract_v0_1.yaml`의 `product` enum + `prompts/*.md` | 파이프라인·화면·권한 게이트 전부 |
| 다른 언어·시장 | vocab 계층에 surface form 추가, `market` enum 확장 | **스키마·enum 코드는 언어 중립** — EN 원석과 KO 음성이 이미 같은 canonical로 합산된다 |
| 다른 도메인(면담 아닌 비정형) | Contract 필드 세트 교체 + `purpose_domain` 매트릭스 재정의 | 상태 머신·검토 큐·evidence 규칙·루프 두 개 |
| 다른 LLM / 사내 승인 환경 | `llm.py` **한 파일**의 구현체 | 프롬프트·스키마·업무 로직 |
| 사내 데이터 플랫폼 이관 | 접속 계층만 | **ANSI SQL만 사용**하도록 처음부터 제약했다 — 같은 스키마·같은 질의를 Snowflake로 그대로 옮긴다 |

가장 넓은 확장은 기술이 아니라 습관이다. Field가 정착하면 **"기록을 남기는 방식"이 팀 단위로 바뀐다.** 그 시점부터는 축적분 정리가 일회성 과제가 되고, 반복 청소가 사라진다.
