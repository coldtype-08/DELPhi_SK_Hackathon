## 한 장 요약

**한 일**: 커넥터(외부 데이터를 자동으로 가져오는 코드)를 짜기 전에, 4개 API가 실제로 쓸 만한지 먼저 호출해봤습니다.

**알아낸 것**: 팀장님이 화면에 적어둔 질문 ①("경쟁 약물의 허가 연령은 어디까지인가")의 **답이 나왔습니다.**
> XCOPRI와 같은 적응증을 가진 경쟁 약물 13종 중 **10종이 이미 12–17세를 커버**합니다.
> 커버하지 못하는 3종 중 하나가 XCOPRI입니다. → 우리 공백은 **"미개척"이 아니라 "뒤처짐"**입니다.

**문제가 된 것**: 호출해보니 **지금 설계로는 연결이 안 되는 지점 6개**가 나왔습니다. 코드로 넘어가기 전에 정리가 필요합니다.

## 2. 질문 ①의 답 — 경쟁 약물의 허가 연령

**어떻게 구했나**: "XCOPRI와 같은 적응증(부분발작)을 가진 약"을 FDA에 물어봤더니 13종이 나왔고, 각각의 허가 문서에서 최소 연령을 읽었습니다.

| 약물 | 허가 최소연령 | 12–17세 쓸 수 있나 |
|---|---|---|
| Pregabalin | 1개월+ | ○ |
| Levetiracetam (Keppra) | 1개월+ | ○ |
| Lacosamide (Vimpat) | 1개월+ | ○ |
| Brivaracetam (Briviact) | 1개월+ | ○ |
| Everolimus | 12개월+ | ○ |
| Topiramate | 2세+ | ○ |
| Eslicarbazepine | 4세+ | ○ |
| Perampanel (Fycompa) | 4세+ | ○ |
| Oxcarbazepine | 6세+ | ○ |
| Zonisamide | 16세+ | ○ |
| Gabapentin | 성인만 | ✕ |
| Lamotrigine | 성인만 | ✕ |
| **XCOPRI (우리)** | **성인만** | **✕** |

**→ 13종 중 10종이 이미 청소년에게 쓸 수 있습니다. 못 쓰는 3종 중 하나가 우리입니다.**

DECISIONS 08/20이 이 화면에 걸어둔 판정 기준 — *"우리 공백이 '미개척'인지 '뒤처짐'인지가 이 한 장으로 판정된다"* — 의 답은 **뒤처짐**입니다.

### 덤으로 보이는 것

"라벨 수"(그 성분으로 나온 허가 문서의 개수)를 세어보면 **제네릭이 얼마나 깔렸는지**가 보입니다.

- XCOPRI **1건** — 제네릭 없음(독점)
- Gabapentin **391건** · Levetiracetam **166건** — 제네릭 포화

즉 *"우리가 못 가는 청소년 구간을 가는 약들은 대부분 이미 제네릭화돼 값이 싸다"* 는 두 번째 층위가 읽힙니다. 다만 이건 정확한 점유율이 아니라 대략적인 신호이므로, 화면에 쓴다면 **"라벨 등재 수"** 라고만 표기해야 합니다.

## 3. ⚠ 데모 각본에 영향이 있습니다

DECISIONS 08/21에 *"8/26 스냅샷을 받아본 뒤 HYP-004의 결말을 리허설 대본에 고정한다"* 고 되어 있습니다. **미리 받아보니 각본 가정과 다릅니다.**

| 가설 | 각본의 가정 | 실제 데이터 |
|---|---|---|
| **HYP-003** (PGTC · 완주 대표) | 임계 도달 → Screen → Board 관통 | PGTC 적응증을 가진 약이 **이미 21종**. Lacosamide 4세+, Perampanel 12세+ 등 → 가설에 **반대되는 근거**가 강함 |
| **HYP-004** (LGS) | 외부 근거가 얇아서 `NOT_BOARD_READY`로 남는 것이 각본 | LGS 적응증을 가진 약이 **이미 10종**. Cannabidiol 1세+, Fenfluramine 2세+ 등 → **근거가 얇은 게 아니라 경쟁약이 이미 자리를 잡은 상태** |

**이건 나쁜 소식이 아닐 수 있습니다.** "아무도 안 갔다"보다 **"우리만 없다"가 더 시급한 논거**입니다.

다만 *"근거가 없으면 순위를 매기지 않는다"* 를 보여줄 가설을 어느 것으로 할지는 다시 정해야 합니다.
**데이터를 각본에 맞추지 않겠습니다** — docs/03 §7의 "캐시 조작 금지" 원칙에 따라, 각본 쪽을 조정하는 판단을 요청드립니다.

## 3.5 질문 ② — ClinicalTrials.gov 연결 점검

> **② 경쟁사는 청소년 시험을 언제 시작했나** — 가설 상세 HYP-001 "왜 지금인가"

**목적은 여기서 결론을 내는 것이 아니라, 커넥터를 붙였을 때 제대로 돌아가는지 확인하는 것입니다.**
데이터를 해석해 "그래서 어떻게 하자"를 정하는 것은 Screen·Board 에이전트의 몫입니다.

### 작동 확인 — 됩니다

경쟁군 14종을 조회했고 전부 응답이 왔습니다. 청소년(12–17) 구간이 포함된 시험이 **총 393건** 잡힙니다.
필요한 값(시작일·연령 범위·상태·스폰서)이 모두 들어 있어, 화면이 요구하는 "언제 시작했나"를 채울 수 있습니다.

### 붙이기 전에 정해야 할 것 5가지

| # | 무엇이 문제인가 | 실측 |
|---|---|---|
| **가** | **한 번에 다 안 온다** | levetiracetam은 시험이 **203건**인데 한 번에 200건까지만 옵니다. 나머지를 받으려면 `nextPageToken`으로 이어 받아야 합니다. **여러 번 나눠 받는 처리가 필요합니다** |
| **나** | **"청소년 시험"의 정의가 없다** | 시험마다 대상 연령이 `1 Month`·`16 Years`·`N Weeks` 등 **10가지 형식**으로 적혀 있습니다. "12–17세가 포함되는가"를 판정하려면 전부 같은 단위로 바꾸는 규칙이 필요합니다 |
| **다** | **상한 연령이 비어 있는 게 정상** | 41%가 상한 없음(= 나이 제한 없음)입니다. 이걸 "값이 없다"로 처리하면 **시험 절반이 사라집니다** |
| **라** | **회사 주도와 연구자 주도가 섞여 있다** | 200건 중 회사(INDUSTRY) 70건, 대학·병원(OTHER) 121건. 섞어 세면 *"이 약은 개발이 활발하다"* 는 **잘못된 신호**가 됩니다. 다행히 `leadSponsor.class` 로 구분됩니다 |
| **마** | **몇 건을 저장할 것인가** | 393건을 다 넣을지, 회사 주도만 넣을지, 최초·최근만 넣을지 정해야 합니다. `external_refs` 한 행에 시험 하나씩이면 행이 수백 개가 됩니다 |

### 조회 조건도 정해야 합니다

지금은 제가 임의로 `약물명 + (epilepsy OR seizures)` 로 걸었습니다. 뇌전증 밖 적응증(편두통 등)을 걸러내려는 것이었는데,
**이 조건을 어디에 적어둘지가 정해져 있지 않습니다.** 질문 ①의 보완 1·2번(환자군에 검색어를 붙이는 것)과 같은 성격의 문제입니다.

### 나온 값 예시 (커넥터가 채울 자리를 보여주기 위한 것)

각 약물이 청소년 포함 시험을 **처음 시작한 시점**이 이렇게 잡힙니다 —
Topiramate 1992 · Levetiracetam 1998 · Lacosamide 2001 · Brivaracetam 2005 · **Cenobamate 2007** · Perampanel 2008 · Fenfluramine 2016.

**이 숫자를 어떻게 읽을지는 우리가 정하지 않습니다.** 화면에 올려놓으면 Screen 에이전트가 근거로 쓰고, Board가 심의합니다.

## 4. 설계 보완이 필요한 7건

호출해보니 **지금 설계로는 연결되지 않는** 지점들입니다.

| # | 드러난 문제 | 왜 지금 설계로는 안 되나 | 어떻게 하면 되나 |
|---|---|---|---|
| **1** | 환자군 값을 그대로 FDA에 못 던진다 | `label_ko`가 "전신 강직-간대발작(PGTC)" — **한국어**. FDA는 `tonic-clonic`으로 씁니다. **영문 적응증어가 스키마에 없음** | 환자군마다 FDA 검색어를 한 칸 추가 |
| **2** | 환자군이 두 종류인데 구분이 없다 | LGS·PGTC는 **질환** → 적응증으로 검색 / 청소년·노인은 **연령** → 허가 문서의 연령을 읽어야 함. **조회 방법이 다른데 코드가 구분할 근거가 없음** | 환자군마다 "질환형/인구형" 표시를 한 칸 추가 |
| **3** | 경쟁 약물 목록의 출처가 정의 안 됨 | 화면엔 **고정 5종**. 테스트해보니 적응증 검색으로 **자동 도출이 가능**하고 그게 더 정확 (13종, Keppra 포함) | 목록을 사람이 정하지 않고 FDA가 정하게 함 |
| **4** | 제네릭 라벨이 섞인다 | 스펙에 **NDA/ANDA 구분이 없음**. Keppra는 라벨이 166건이라 아무거나 잡히면 **틀린 연령**이 나옴 | 오리지널(NDA) 문서만 보도록 조건 추가 |
| **5** | 판정 결과가 3단인데 담을 곳이 없다 | **확정 / 성인전용(명시) / 판정보류** 세 가지가 나오는데, `external_refs` 테이블에 **상태를 적을 칸이 없음** | 상태 칸과 사유 칸 추가 |
| **6** | 라벨 원문을 어디에 둘지 미정 | **캐시(전량)** 와 **payload_json(화면용)** 의 역할 분담이 스펙에 없음 | 캐시엔 받아온 그대로 전부, DB엔 화면이 그리는 값만 |
| **7** | **"경쟁사"를 약물명으로만 판정하면 틀린다** | 같은 성분을 **라이선스 파트너**가 다른 코드명으로 개발 중일 수 있음 (ONO-2017 = 세노바메이트 사례). 이걸 경쟁사로 세면 **시장 판단이 반대로 뒤집힘** | 시험의 실제 개입 약물 확인 + 자사·파트너 스폰서 목록을 두고 걸러냄 |

### 4.1 왜 "판정보류"를 빈칸으로 두면 안 되나

연령을 못 읽는 경우가 생길 수 있습니다. 그때 **추측해서 채우면 안 됩니다.**

DECISIONS 08/20: *"틀린 시장 사실은 틀린 가설보다 되돌리기 어렵다 — 스크린샷이 사내에 돌아다닌다."*

대신 **"판정 보류 · 이유 · FDA 원문 링크"** 를 함께 보여주면, 화면이 "못 했다"가 아니라 **"확인하고 판단을 보류했다"** 로 읽힙니다. `NOT_BOARD_READY(사유 코드)`와 같은 문법입니다.

> **실측 결과 판정보류는 0건이었습니다.** 아래 4단계로 순서대로 시도하면 13종 전부 판정이 나왔습니다.
> ① 오리지널(NDA) 문서 우선 → ② 적응증에서 연령 읽기 → ③ 실패 시 "소아 사용" 항목 재시도 → ④ 그래도 없으면 "성인 대상"이라고 적혀 있는지 확인
