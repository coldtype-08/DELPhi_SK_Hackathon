### 로그인 방법

**비밀번호가 없습니다.** 첫 화면에서 **역할(페르소나)을 고르는 것이 로그인**입니다. 권한 분리가 실제로 동작하는 것을 보여주기 위한 장치이며, 실제 인증(사내 SSO)은 파일럿 단계의 몫입니다.

| 고를 역할 | 무엇을 보게 되나 |
|---|---|
| **`ADMIN`** ← **처음 오셨다면 이걸 고르세요** | 전 영역 열람 (승인·쓰기 권한은 없음) |
| `CLINICAL_STRATEGY` | 기본 업무 역할 — 가설·근거·승인 |
| `COMMERCIAL` | **의도적으로 덜 보입니다.** 원문·의료진 식별자 접근 불가, 집계만. 미승인 적응증(Development) 관련 항목은 아예 목록에서 사라집니다 |
| `SAFETY` | 이상사례(AE) 후보 — 다른 역할에는 보이지 않는 별도 경로 |
| `DATA_STEWARD` | 스키마 변경 승인 |

> 상단 스위처로 역할을 바꿔 **같은 화면이 역할에 따라 달라지는 것**을 비교하실 수 있습니다. `COMMERCIAL`로 바꿨을 때 항목이 줄어드는 것은 오류가 아니라 이 제품의 핵심 기능입니다.

## 2. 사용 방법 — 6단계 투어 (약 12분)

각 단계의 **"확인할 것"** 이 그 단계의 합격 기준입니다.

| # | 화면 | 할 일 | 확인할 것 | 구현 |
|---|---|---|---|---|
| ① | Console `/contract/provenance` | 스크롤 | **스키마 자체를 AI가 초안 내고 사람이 확정한 기록.** 어떤 항목이 왜 채택/제외됐는지 원문 인용까지 따라갈 수 있다 | ⟨9/2 갱신⟩ |
| ② | Console `/review` | 검토 큐 첫 항목 → 추출값 클릭 → **승인** | 추출값을 클릭하면 **원문의 해당 문장이 형광펜으로 잡힌다**(근거 없는 값은 저장되지 않음). 승인하면 홈 KPI가 **즉시 +1** | ⟨9/2 갱신⟩ |
| ③ | **Field** (휴대폰) `/capture` | 동의 → 한국어 면담 입력 → 카드 승인 | 현장에서 **생성 시점에 이미 구조화**되어 들어온다. 이 한국어 수집이 ②의 **영문 문서와 같은 집계에 합산**된다 (언어 중립 canonical) | ⟨9/2 갱신⟩ |
| ④ | Console `/` → `/hypotheses` | 후보 레이더에서 임계 도달 항목 → 가설 카드 | 사람이 "한번 봐야겠다"고 결심하기 전에 **시스템이 먼저 알려준다.** 반복 ≥5 ∧ 독립 의료진 ≥3에서 가설이 자동 생성된다 (숫자는 전부 SQL 계산) | ⟨9/2 갱신⟩ |
| ⑤ | `/hypotheses/HYP-003` | Screen 근거 → Board 회의록 → **승인** | 다중 에이전트가 **공개 근거(PubMed·ClinicalTrials.gov·openFDA)로 교차검증**한 뒤 심의한다. **승인은 사람만 한다.** 승인 즉시 후속 질문이 **Action Item으로 Field 체크리스트에 내려간다** → Field `/`에서 확인 | ⟨9/2 갱신⟩ |
| ⑥ | `/contract` | SCP 승인 → Field 새로고침 | 스키마에 없던 반복 개념이 **Schema Change Proposal**로 올라오고, 승인하면 **Field 입력 폼이 실제로 바뀐다** | ⟨9/2 갱신⟩ |

### 더 보실 것이 있다면

| 화면 | 무엇 |
|---|---|
| `/market` | 경쟁 환경 — **공개 출처만.** 개인 식별 0건, 예측선 없음 |
| `/safety` | 이상사례 후보 분리 + Critic이 **막은 것**의 기록 |
| `/hypotheses` 의 `NOT_BOARD_READY` 카드 | **외부 근거가 얇으면 순위를 매기지 않는다.** 비어 있는 것이 정상 동작 |
| 데이터 원장 탭 (`/draft.html`) | 화면 뒤의 테이블 전 컬럼. 역할에 따라 **403과 행 억제**가 실제로 걸리는 것을 SQL 수준에서 확인 |

## 3. 결과물 본체

### 무엇이 도는가

```
축적분(영문 Word·PDF 320건) ──▶ Sense 추출 ──┐
                                            ├──▶ 같은 Data Contract ──▶ SQL 집계 ──▶ 가설 자동 생성
유입분(Field 한국어 면담)   ──▶ 생성 시 구조화 ─┘                                        │
        ▲                                                                              ▼
        └──── Action Item(체크리스트) ◀──── 사람 승인 ◀──── AI 이사회 심의 ◀──── 다중 에이전트 교차검증
```

**두 개의 루프가 있고, 도는 주기가 다릅니다.**
- **실행 루프 (매 심의마다)**: 심의 → 사람 승인 → Action Item → Field 체크리스트 → 다음 면담이 그 질문을 참조해 수집 → 집계로 되돌아옴
- **구조 루프 (드물게)**: 스키마 밖 개념이 반복 → SCP → Steward 승인 → Contract v0.2 → 입력 폼 변경

### 화면의 모든 판단 정보는 5단계로 구분 표시됩니다

`관찰된 사실` · `통계적 패턴` · `AI의 해석` · `전략적 제안` · `승인된 실행`
— AI가 말한 것과 데이터가 말한 것을 섞지 않는 것이 이 제품의 기본 규칙입니다.

### 지키기로 하고 코드로 강제한 것

| # | 규칙 | 강제 방식 |
|---|---|---|
| 1 | **수치는 AI가 계산하지 않는다** | 반복 횟수·출처 수·추이는 전부 SQL |
| 2 | **모든 추출값에 원문 근거 포인터 필수** | 원문 위치가 없거나 불일치하면 **저장 거부** |
| 3 | **승인된 데이터만 집계에 쓴다** | AI 추출값은 `CANDIDATE`로 시작 |
| 4 | **스키마는 AI가 바꿀 수 없다** | 변경은 SCP → 사람 승인 → 새 버전. 과거 데이터는 생성 당시 버전 보존 |
| 5 | **미승인 적응증은 상업 액션과 자동 연결 금지** | `label_scope` 필드 + 역할별 쿼리 게이트 |
| 6 | **이상사례 후보는 별도 경로** | 일반 집계 쿼리에 한 건도 섞이지 않는다 |
| 7 | **하지 않는 것** | 매출 예측 · 개별 의료진 처방성향 점수화 · 프로모션 메시지 생성 |

## 4. 잘 안 될 때

| 증상 | 대응 |
|---|---|
| 화면이 비어 있다 | 다른 심사위원이 방금 리셋했을 수 있습니다. **매일 자정(KST) 초기 상태로 자동 리셋**됩니다. 새로고침 후 다시 확인해 주세요 |
| 흰 화면 | 다른 브라우저(사파리)나 시크릿 창으로 열어 주세요 |
| 외부 데이터가 안 나온다 | 외부 공개 API는 **캐시된 스냅샷**을 우선 사용합니다 (조회 기준 시점이 화면에 표기됩니다). 네트워크와 무관하게 동작합니다 |
| 그래도 막힌다 | `4_제작과정/BLOCKERS.md`에 우리가 겪은 사고와 해결이 기록돼 있습니다 |
