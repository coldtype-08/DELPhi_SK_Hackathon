# 제출물 작업 폴더 — Google Drive 미러

> **이 폴더는 제출용 Google Drive 폴더의 로컬 미러다.** 폴더 이름은 주최측 구조와 **1:1로 같다.**
> 주최측 명시 경고: *"이름을 바꾸거나 지우거나 새로 만들지 마세요. 평가는 이 구조를 그대로 읽어가는 방식이라, 이름이 다르면 그 항목은 비어 있는 것으로 처리됩니다."*
> 그래서 **여기서 이름을 손대면 안 된다.** 파일을 추가할 때는 해당 폴더 **안에만** 넣는다.
> 마감: **2026-09-03(목) 23:59.** 이 시점의 Drive 폴더 상태가 그대로 평가된다 (마감 후 변경 반영 없음).

## 왜 레포에도 두는가

Drive에 바로 쓰면 세 가지를 잃는다: ① 버전 이력 ② 3인 동시 편집 시 충돌 감지 ③ 코드·문서와의 정합 확인.
그래서 **레포에서 쓰고 Drive로 올린다.** 레포가 초안이고 Drive가 제출본이다.
주최측 경고 중 *"4번 폴더를 마감 직전에 몰아서 쓰는 경우 — 2주 뒤에 기억으로 복원한 개발 일지는 티가 납니다"* 는 이 방식으로만 피할 수 있다. 일지는 **당일에** 쓴다.

## 업로드 방법 (9/2 조립일에 한 번, 그 전엔 4번만 수시)

1. Drive의 같은 이름 폴더를 열고, 이 폴더 안의 파일을 **그대로 올린다.**
2. **각 폴더의 `README`는 Google Docs로도 만든다.** Drive의 `.md` 미리보기는 표를 `|`가 박힌 평문으로 보여준다 — 심사위원이 표를 못 읽으면 안 쓴 것과 같다.
   - Docs 설정에서 **"마크다운 사용"을 켜고** 본문을 붙여넣으면 헤딩·표가 변환된다. 변환 후 표가 깨졌는지 눈으로 확인한다.
   - 원본 `.md`도 같은 폴더에 함께 둔다 (정본은 레포).
3. 올린 뒤 **다른 계정/시크릿 창으로 열어 본다.** 권한이 막혀 있으면 심사위원에게는 빈 폴더다.

## 반출 금지 — 올리기 전 체크리스트 (위반 시 제출물 삭제·자격 박탈)

주최측 보안 가이드 한 줄 요약: **"사내 데이터는 원본 그대로 나갈 수 없습니다."** Drive 업로드와 Claude 입력창 붙여넣기가 **같은 반출**이다.

- [ ] 사내 문서 원문·스크린샷·DB 덤프·로그 원문이 없다
- [ ] 개인정보(성명·연락처·이메일·사번)가 없다 — **팀원 사내 이메일도 안 된다**
- [ ] API 키·비밀번호·토큰·사내 시스템 주소가 없다 (`.env`는 제출물에서 제외)
- [ ] 화면·데이터가 **전부 합성**임이 각 문서 첫 줄에 적혀 있다
- [ ] **내부 활동량 수치가 필요 이상으로 구체적이지 않다** — 의료진 접점은 "연간 수백 명" 같은 규모 표기까지만 (`docs/08 §1.2` 표기 원칙)

> 판단이 애매하면 올리지 않고 아침 싱크 안건으로 올린다. "요약해서 넣는 것"도 반출이다.
