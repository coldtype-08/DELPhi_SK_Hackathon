# 3_검증결과 — 검증 방법 · 검증 기록

> 데이터는 전부 합성입니다. 그래서 **정답(planted signal)을 알고 있고**, 추출 결과를 정답과 대조할 수 있습니다.
> 담당: 소정 (기록 수집) · 전원 (실행). 상태: **⟨9/2 확정⟩** — 아래 표의 `기록` 칸이 채워지는 것이 이 폴더의 진행률입니다.

## 0. 우리가 증명해야 하는 것 두 가지

주최측 기준: *"예시 데이터에서만 되는 것이 아니라 실제 사용 환경과 유사한 조건에서도 작동하는지, 그 검증 결과가 함께 제시되어 있는지"* (재현 가능성 10점)

1. **같은 입력에 같은 결과가 나온다** (재현성) — LLM을 쓰면서 이걸 증명하지 않으면 시연은 운이다
2. **정해진 시연 문서 밖에서도 작동한다** (일반화) — 320건 중 시연에 쓰지 않은 문서로 확인한다

## 1. 검증 방법 — 6종

| ID | 무엇을 검증 | 방법 | 합격 기준 | 담당 | 기록 |
|---|---|---|---|---|---|
| **V1** | 시나리오 완주 | 리셋한 DB에서 ①~⑥ 전 단계 실행 | **3회 연속** 성공 · 12분 이내 | 전원 | `records/V1_*.md` |
| **V2** | 추출 재현성 | 같은 문서 3회 추출 → 결과 비교 (temperature 0) | 필드값·근거 오프셋 **완전 일치** | 인혁 | `records/V2_*.md` |
| **V3** | 추출 정확도 | 합성 코퍼스 **ground truth 대조** — planted signal 대비 | reviewer acceptance **90% 이상** (기획서 §6-2 목표치) | 건태 | `records/V3_*.md` |
| **V4** | 절대 규칙 회귀 | 규칙 위반을 **시도**해 막히는지 확인 (아래 §1.1) | 4종 전부 차단 | 인혁 | `records/V4_*.md` |
| **V5** | 환경 다양성 | 오프라인·브라우저 3종·모바일·엣지 케이스 | 전 조합 완주 | 소정 | `records/V5_*.md` |
| **V6** | 처음 보는 사람 | **팀원 아닌 1인**에게 `2_결과물` README만 주고 완주 시킴 | 질문 없이 ⑥까지 도달 | 건태 | `records/V6_*.md` |

> **V6이 이 폴더의 핵심이다.** 심사 방식이 "심사위원이 직접 사용해 본다"이므로, 팀원이 되는 것은 증명이 아니다. 막힌 지점은 그대로 기록하고 문서를 고친다.

### 1.1 V4 — 규칙 위반을 일부러 시도한다

| 시도 | 기대 결과 |

## 2. 검증 기록

`records/` 폴더에 **실행할 때마다** 한 파일씩 쌓습니다. 양식: `records/_TEMPLATE.md`
파일명: `V{번호}_{YYYY-MM-DD}_{실행자}.md`

| 회차 | 날짜 | 대상 | 결과 | 파일 |
|---|---|---|---|---|
| ⟨첫 기록은 8/30 체크포인트 #2⟩ | | | | |

> **실패 기록도 남깁니다.** 3회 중 1회 실패한 것을 "3회 성공"으로 적으면 재현 가능성 항목 전체의 신뢰가 사라집니다. 실패 → 원인 → 수정 → 재실행이 그대로 `4_제작과정/BLOCKERS.md`의 재료가 됩니다.

## 3. 합성 데이터라서 가능한 것 / 불가능한 것

| | |
|---|---|
| 가능 | **정답 대조** (planted signal 위치·값을 안다) · **완전 재현** (같은 시드 → 같은 코퍼스, LLM 미사용 생성기) · 안전한 공개 |
| 불가능 | 실제 문서의 표기 다양성·오타·손글씨 스캔 등 실제 노이즈. → 코퍼스는 3인이 각 20블록씩 육안 검수해 현실성을 맞췄고(8/22), **남은 격차는 이 문서에 명시한다** |

코퍼스 규모: 문서 **320건** · 인사이트 단위 **1,118** · 의료진 **300인** · 기간 2021~2026 (상세: `docs/03_SYNTHETIC_DATA.md`)
