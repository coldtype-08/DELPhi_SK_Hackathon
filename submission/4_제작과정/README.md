# 4_제작과정 — 계획대로 진행했나, 막힌 지점을 어떻게 풀었나

> 이 폴더는 **집요함과 패기 15점**이 보는 곳이다. 주최측 문장: *"결과물만으로는 드러나지 않는 부분이라 별도로 기록해 주셔야 확인할 수 있습니다."*
> 그리고 자주 틀리는 것으로 지목된 것: *"4번 폴더를 마감 직전에 몰아서 쓰는 경우 — 2주 뒤에 기억으로 복원한 개발 일지는 티가 납니다."*
> → **그래서 이 폴더만 매일 갱신한다.** 다른 폴더는 9/2에 확정하지만 여기는 매일이다.

## 무엇이 들어 있나

| 파일 | 내용 | 갱신 |
|---|---|---|
| [`WBS.md`](WBS.md) | 작업 분해 구조 — 8개 작업 묶음의 산출물·담당·계획·실적·상태 + **계획 변경 이력과 그 이유** | 상태가 바뀔 때 |
| [`minutes/`](minutes/) | 회의록 | 회의마다 |
| [`daily/`](daily/) | **개발 일지 — 3인 각자, 매일** | 매일 |
| [`BLOCKERS.md`](BLOCKERS.md) | 막힌 지점과 해결 과정 (증상 → 어떻게 찾았나 → 원인 → 해결 → 배운 것) | 겪을 때마다 |

## 개발 일지 쓰는 법 (3분)

```bash
# 1) 오늘 커밋에서 초안을 만든다 (3인분 한 번에)
python3 scripts/daily_report.py

# 특정 날짜 / 특정 사람만
python3 scripts/daily_report.py --date 2026-08-22 --author 소정
```

→ `daily/2026-08-22_소정.md` 가 생성된다. **커밋 목록·WBS 추정·결정 기록은 자동으로 채워지고**, 사람이 채울 칸은 세 개다.

1. **막힌 것** — 없으면 "없음". 있는데 안 적으면 그날 일이 사라진다.
2. **내일 할 것** — 아침 싱크가 이걸 읽는다.
3. **오늘의 한 줄** — 하루를 한 문장으로.

> 스크립트는 **이미 있는 파일을 덮어쓰지 않는다** (`--force` 필요). 사람이 고친 내용이 날아가지 않게.

Claude Code 세션 커밋은 author가 `Claude`로 찍혀 **누구 작업인지 git에 남지 않는다.** 스크립트가 건드린 경로의 오너십으로 추정해 `※`를 붙이니, 자기 일지에서 남의 것이 보이면 지우면 된다. 새 git 신원이 생기면 `scripts/daily_report.py`의 `IDENTITIES`에 한 줄 추가.

## 왜 자동 생성하나

기억으로 복원한 일지는 티가 난다 — 그런데 그 이유는 게으름이 아니라, **하루 끝에 "오늘 뭐 했지"를 떠올리는 게 실제로 어렵기 때문**이다. 커밋은 이미 그 답을 갖고 있다. 그래서 사실(무엇을 고쳤나)은 git에서 가져오고, 사람은 **git이 모르는 것**(왜 막혔나, 무엇을 포기했나)만 쓴다.

| 막혔을 때 어떻게 했나 | `BLOCKERS.md` 10건 — 각 항목의 **"어떻게 찾았나"** |
| 매일 했나 | `daily/` 파일 수 · 커밋 이력 |
