## 막힌 것

**1) 실측 규모를 잘못 해석했다 (해결 — 정정)**
- **증상**: raw data 의 "의사 110명"을 *만난 의사 수*로 읽고, 적어 보이는 이유를 "재방문 때문"이라고 설명했다. 틀렸다 — **KOL 명부 수**였다.
- **시도**: 뭉개는 표현("수백 명")으로 바꾸는 안을 검토했다가 기각. 심사 기준이 "문제 정의의 명확성"이라 **검증 가능한 진술이 뭉갠 진술보다 강하다.**
- **결과**: 두 모집단을 분리해 다시 씀 — ① 접점 의료진(주 7~25명 → 연간 수백 명 규모) ② KOL 명부(약 110명, 2025년 9월까지 집계분). 정정하고 나니 **두 숫자의 간격 자체가 AS-IS의 위치**라는 더 강한 논거가 나왔다: 연간 수백 명을 만나는데 체계가 따라가는 것은 명부 안쪽이고, 신호는 명부 밖에서 더 많이·먼저 나온다. 우리 임계값이 KOL 여부를 묻지 않는 이유가 여기에 연결된다.
- `BLOCKERS.md` 에 올릴 것인가: 아니오 (기술 장애가 아니라 해석 정정 — `DECISIONS.md` 에 정정으로 남김)

**2) 일지 자동화가 한글 경로를 못 읽었다 (해결)**
- **증상**: 오늘의 일지 초안에서 `submission/` 커밋의 WBS 가 `8.x` 가 아니라 `0.1` 로 나왔다. 파일 13개가 `submission/` 인데 왜 문서 작업으로 분류되나.
- **시도**: 생성된 표를 그대로 믿지 않고 커밋의 파일 목록을 직접 세어 봤다 → `"submission/4_제작과정/..."` 처럼 **경로가 인용부호와 8진 이스케이프로 나오고 있었다.**
- **결과**: 해결. git 이 비ASCII 경로를 기본으로 인용한다(`core.quotepath`). 우리 폴더 이름이 전부 한글이라 **경로 기반 분류가 통째로 무력화**될 상황이었다. `-c core.quotepath=false` + 인용부호 제거.
- **배운 것**: 자동 생성물은 **한 번은 손으로 검산해야 한다.** 그럴듯한 값이 나오면 틀린 걸 모른다.
