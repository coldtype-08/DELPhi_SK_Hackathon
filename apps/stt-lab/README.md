# DELPHi STT Lab — 실시간 STT 3종 비교

Soniox · Gladia · Deepgram을 **같은 음성·같은 조건**으로 나란히 돌려보고, 어느 것을 Field 앱에 쓸지 정하기 위한 로컬 전용 도구입니다.

- 배포하지 않습니다 (`railway.json` 없음)
- API 키는 화면에서 입력하고 **브라우저에만** 저장됩니다 (커밋·서버 전송 없음)
- 결과가 3탭에 각각 남으므로 비교가 됩니다

## 1. 준비 — API 키 3개

| 서비스 | 발급 |
|---|---|
| Soniox | https://console.soniox.com/ |
| Gladia | https://docs.gladia.io/chapters/introduction/getting-started |
| Deepgram | https://console.deepgram.com/ |

세 개를 다 받지 않아도 됩니다. 받은 것만 해당 탭에서 테스트하면 됩니다.

## 2. 테스트 음성 준비

세 가지 중 하나면 된다.

1. **사람이 직접 읽는다** — 음성 파일이 필요 없다. 마이크 입력 방식을 `사람이 말함`으로 두고
   두 사람이 `scripts/stt_eval/TEST_SCRIPTS.md` 의 대본을 번갈아 읽는다. **판정 재료로는 이것이 정본이다.**
2. **랩에서 만든다** — 상단 「대본 → 음성 (Gemini TTS)」 탭. 화자 2명을 한 번에 만든다 (§6).
   팀원 여러 명이 **같은 소리로** 돌려봐야 할 때 이 방법을 쓴다.
3. **espeak-ng** — 배선 확인용이다. **판정에는 쓰지 않는다** (기계음이라 "17세→70세" 같은 실제 오인식이 재현되지 않는다).

```bash
# 3번을 쓸 때만
brew install espeak-ng                 # mac
sudo apt-get install -y espeak-ng      # linux
winget install eSpeak-NG.eSpeak-NG     # windows
python3 scripts/stt_eval/gen_test_audio.py   # → scripts/stt_eval/audio/*.wav
```

**P1은 초안입니다** — 확정 용도는 8/24 STT 3종 비교 하나뿐이고, 통합 테스트·제출물·발표 입력으로 쓸지는 오너 판단입니다 (`TEST_SCRIPTS.md`).

## 4. 쓰는 순서

1. **공통 조건**에서 정합니다
   - 채점 대본: `D1`(실제 시나리오, 기본값) · `T1`(한·영 혼용) · `P1`(HYP-003 초안) — 재생할 음성과 맞춥니다
   - 언어 설정 / 화자 분리 / 부스팅 on-off
   - **마이크 입력 방식** — 아래 §4.1
   - **WAV 파일** — 탭별 「파일로 시작」을 쓸 때만 필요합니다 (배선 확인용)
2. 탭을 고르고 **API 키**를 붙여넣습니다 (한 번 넣으면 브라우저에 저장됩니다)
3. **모델**을 고릅니다
   - Deepgram: 세 대본 모두 한국어이므로 `nova-3` (`nova-3-medical`은 한국어 미지원)
4. **「동시 시작」** (권장) 또는 탭별 「마이크로 시작」·「파일로 시작」 — §4.1
5. 탭을 옮겨 같은 소리에 대한 세 결과를 비교

### 4.1 넣는 방법 — 기본은 「3종 동시 실행」

실제 시연은 **사람이 말하거나 음성 파일을 스피커로 트는** 방식이다. 그러니 인식률도 그 조건에서 재야 한다.
파일 업로드는 마이크·공기·잡음을 통째로 건너뛰므로 실전과 다른 것을 재게 된다.

다만 세 서비스를 각각 따로 재생하면 매번 소리가 달라져, 점수 차이가 서비스 차이인지 재생 차이인지 알 수 없다.
그래서 **마이크 하나를 세 서비스에 동시에 흘린다** — 한 번의 발화·재생을 셋이 같이 듣는다.

| | 방법 | 언제 |
|---|---|---|
| **A** | **3종 동시 실행** (화면 상단 「동시 시작」) | **기본.** 실제 조건 + 공정 비교가 동시에 성립 |
| B | 탭별 「마이크로 시작」 | 한 서비스만 다시 볼 때 |
| C | 탭별 「파일로 시작」 | 배선 확인용. 마이크를 건너뛰므로 **판정에는 쓰지 않는다** |

**A를 쓰는 순서**

1. 세 탭에 API 키를 각각 넣습니다 (키가 없는 서비스는 그 회차에서 자동으로 빠집니다)
2. 공통 조건에서 **마이크 입력 방식**을 고릅니다
   - `사람이 말함` — 두 사람이 대본을 번갈아 읽습니다. **8/24 판정용**
   - `스피커로 재생` — WAV를 스피커로 틉니다
3. **「동시 시작」** → 말하거나 재생 → **「중지」**
4. 탭을 옮겨 다니며 같은 소리에 대한 세 결과를 비교합니다

**`스피커로 재생`을 쓸 때 반드시 그 설정으로 바꿉니다.** `사람이 말함`으로 두면
브라우저의 에코 제거가 스피커에서 나온 소리를 에코로 판정해 **지워버립니다** — 전사가 비거나 토막나서
서비스 성능이 나쁜 것처럼 보입니다. `스피커로 재생`은 에코 제거·잡음 억제·자동 게인을 전부 끕니다.

- 스피커 볼륨 60~70%, 마이크와 30cm 이내. 노트북 내장 스피커·마이크로 충분합니다.
- 회차마다 소리가 달라지므로 **회차 간 점수는 비교하지 않습니다.** 비교는 한 회차 안의 세 서비스끼리 합니다.

## 5. 화면이 보여주는 것

| 영역 | 내용 |
|---|---|
| 전사 | 화자 라벨(`0`/`1`) + 확정(진한 글씨)·잠정(흐린 이탤릭) 구분 |
| 첫 응답 / 최종 | 시작부터 첫 글자까지 ms, 마지막 확정까지 ms |
| 핵심 토큰 채점 | `TEST_SCRIPTS.md`의 토큰 히트(초록)·미스(빨강). ★는 틀리면 데모가 깨지는 항목 |
| 원시 응답 | 벤더가 보낸 JSON 그대로 — 오류 메시지 확인용 |

**전체 정확도보다 핵심 토큰이 우선입니다.** "하하"를 놓치는 건 무해하지만 "17세"를 놓치면 대표 가설 HYP-001의 근거가 사라집니다.

## 6. 확인이 안 끝난 것 — 실행하면 답이 나옵니다

| 항목 | 어떻게 판정하나 |
|---|---|
| **Soniox WebSocket 경로·`audio_format`** | 공개 문서를 열지 못해 추정값입니다. 틀리면 "원시 응답"에 서버 오류가 뜨고, **엔드포인트 칸에서 바로 고칠 수 있습니다** |
| **Gladia 실시간 화자분리** | 정본 스펙(요청 OpenAPI·응답 asyncapi) 어디에도 없는데 산문·SDK에는 나옵니다. 화자 분리를 켜면 `diarization: true`를 일부러 보냅니다 → **422면 미지원 확정, 201이면 지원** |
| 부스팅 용어 한도 | Deepgram은 500 tokens(문서 확인). Soniox·Gladia는 미확인 — 40개를 실제로 넣어보면 압니다 |

## 6. 대본 → 음성 (Gemini TTS)

상단 **「대본 → 음성 (Gemini TTS)」** 탭. 판정용 음성을 랩 안에서 만든다.

**왜 랩에 넣었나** — 판정 음성은 사람 녹음이 정본이지만(§4.1 C), 팀원 여러 명이 **같은 소리로** 돌려보려면
재현 가능한 고정 파일이 필요하다. espeak-ng 합성음은 품질이 판정에 못 미쳤고(DECISIONS 08/22),
상용 TTS는 웹에서 만들어 내려받는 왕복이 번거로워 대본·목소리·지시문을 한 화면에 뒀다.

**화자 2명을 한 번의 호출로 만든다** — `multiSpeakerVoiceConfig`(google-genai SDK 타입에서 확인).
MSL·HCP에 **다른 목소리**를 주지 않으면 화자 분리를 검증할 수 없어 컷오프 4개 중 하나가 빠진다.

쓰는 순서
1. Gemini API 키를 넣는다 (STT 탭과 같은 원칙 — 브라우저 localStorage에만, 커밋·전송 없음)
2. **「모델 목록 불러오기」** — 기본 모델명은 추정값이다. 계정에서 실제로 쓸 수 있는 이름을 받아 고른다
3. 대본을 고르고(`D1`·`T1`·`P1`) 화자별 목소리를 넣는다
4. **「음성 만들기」** → 들어보고 → **「WAV 저장」** 또는 **「STT 비교 탭에 넣기」**

**추측하지 않는 것 두 가지**
- **모델 이름** — 벤더 목록에서 받아온다
- **목소리 이름** — 자유 입력이다. 문서를 열 수 없어 후보 목록(`Puck`·`Kore`…)이 **확인되지 않은 이름**이므로,
  틀리면 벤더 오류가 화면에 그대로 뜬다. AI Studio에서 실제 이름을 확인해 바꿔 넣는다

**읽기 지시문이 핵심이다.** T1의 `XCOPRI`·`lamotrigine`·`DDI`·`titration`이 영어권 발음으로 읽히면
우리가 겪을 코드스위칭 난이도가 아니라 쉬운 문제를 풀게 된다. 기본 지시문에 "한국인이 한국어 문장 안에서
말할 때의 발음으로" 조건을 넣어 뒀다 — 결과를 듣고 조정한다.

**구현 메모**
- Gemini TTS 응답은 **헤더 없는 raw PCM**(`audio/L16;codec=pcm;rate=…`)이라 WAV 헤더를 붙여야 재생된다.
  그 변환을 `app/api/tts/route.ts`가 한다. 샘플레이트는 응답 mimeType에서 읽고, 못 읽으면 24000을
  가정한 뒤 **화면에 그렇게 표시한다**(하드코딩해 조용히 틀리지 않기 위해).
- 라우트를 둔 다른 이유는 CORS다 — `generativelanguage.googleapis.com`의 브라우저 허용 여부가 확실하지 않다.
