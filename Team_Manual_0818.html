2. 파일 소유 — 이 표가 충돌을 막는다

내 줄에 있는 파일만 고친다. 남의 줄을 고쳐야 하면 아래 3번 규칙.

경로오너무엇
docs/02_DATA_CONTRACT.md
backend/app/contract/*.yaml		 건태스키마 정의
backend/app/prompts/*.md 건태AI에게 주는 지시문
backend/app/**/*.py
scripts/**		 인혁엔진 구현 전부
apps/field/** 소정현장 수집 앱

apps/console/app/page.tsx

apps/console/app/safety/**		 소정대시보드·검토 화면
apps/*/app/globals.css
layout.tsx · nav.tsx · 공통 컴포넌트		 소정디자인 일관성은 한 사람이
왜 이렇게까지 나누나 — 두 사람이 같은 파일을 고치면 git이 충돌을 내고, 그걸 푸는 데 초보는 한 시간을 쓴다. 화면마다 파일이 따로인 구조라, 표만 지키면 충돌은 0이다.

3. 규칙 세 개

  • 규칙 1남의 파일을 고쳤으면 짧게 고치고 즉시 올린다. 커밋 메시지에 [cross] 붙이고 메신저에 한 줄. 오래 붙들고 있으면 상대가 받을 때 충돌한다.
  • 규칙 2API 응답 모양을 바꾸면 docs/04_API_SPEC.md를 같은 커밋에서 고친다. 문서가 먼저, 코드가 나중.
  • 규칙 3스키마는 아무도 코드로 못 바꾼다. 새 항목이 필요하면 SCP(변경 제안) → 승인 → 새 버전. 이게 제품의 정체성이다.

4. 하루 리듬

git 명령을 외울 필요 없다. 전부 Claude에게 말로 시킨다.

시작
“git pull 하고 시작해”
남이 올린 최신 코드를 받는다. 이걸 빼먹으면 충돌한다.
작업
하루 한 덩어리
완료 기준이 분명한 것 하나. “화면 만들기”가 아니라 “입력하면 카드가 뜬다”.
끝
“커밋하고 푸시해줘”
＋ docs/LOG.md에 한 줄. 길게 쓰지 말 것.
3분 뒤
배포에 반영
올린 코드가 실제 주소에 뜬다. 폰으로 열어서 확인.
30분 룰 — 30분 막히면 혼자 붙들지 말고 에러 메시지를 통째로 복사해서 메신저에. 요약해서 보내지 말 것. 대부분 5분이면 풀린다.
